# 破壞性測試安全與隔離原則 (Safe Destructive Testing Rule)

- 當使用者要求「資料庫升級 / 降級 (Upgrade / Downgrade)」、「還原資料庫」、「清理資料」或任何可能觸發 `DROP TABLE`、`DELETE` 的指令時，Agent **嚴禁直接在當前預設環境下執行**。
- **強制執行前檢核**：
  1. **環境隔離**：在執行如 `alembic downgrade base` 或重製資料庫腳本前，**必須**透過環境變數 (例如設定 `CRAWLER_DB_URL=sqlite:////tmp/test.db`) 將連線導向臨時的測試資料庫。
  2. **檔案備份**：若無法使用記憶體或臨時資料庫，且必須操作實體檔案 (如 `db/*.db`)，**必須**在下達破壞性指令前，先複製並備份該資料庫檔案。
  3. **最終確認**：除非使用者已明確表明「我不在乎資料，請直接砍除」，否則若指令具備無法復原的破壞性，必須在執行前與使用者做最終確認。
- **嚴格禁止**：為了圖方便而忽略隔離機制，直接對開發或生產環境中的持久化資料庫執行 DDL Drop 或 Delete 指令。
